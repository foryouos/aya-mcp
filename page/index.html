MCP 服务已内置于 AYA 桌面端

让 AI 直接操控你的 Android 设备

AYA 内置一个只监听 127.0.0.1 的 MCP（Model Context Protocol）服务，把手机能力封装成 73 个 aya_* 工具。在 CodeBuddy、WorkBuddy、Claude 里说一句"打开设置，把字体调到最大并截图"，剩下的交给 AI —— 不用再写脚本、跑命令、粘输出。
同一套面板也支持 带 adb 的 Linux 工控主板（RK3568 / RK3576 · Debian / Ubuntu / Buildroot / Yocto）。

Model Context Protocol

MCP 是什么？为什么手机需要它

MCP 是 AI 客户端与工具之间的开放协议。过去 AI 只能"教你怎么操作手机"，现在它能自己调工具、看结果、再决定下一步——AYA MCP 把 adb 的几十年积累翻译成 73 个标准工具。

会说人话就够了

不用记 adb shell am start -n ...。描述目标，AI 自己选工具、组合调用，失败还会自我纠正。

看得见界面，不只是命令

aya_ui_dump 给带坐标的层级树，aya_screencap 回传截图，AI 既读结构也看画面。

一次调用干完一串动作

aya_batch 串行执行最多 20 个动作，避开播放器控制栏这类 1–3 秒就消失的控件。

上下文成本差 24 倍

一次层级读取，aya 回 3.9 KB（约 1.2k tokens），u2 回 93 KB（约 30k）。长任务里这比毫秒差距更致命。

少一次模型往返

aya_tap 默认回传点击后的新界面；u2 要 AI 自己写代码、解析 XML，再喂回上下文。

u2 没有的能力

事件订阅、事件驱动等待、串口启动日志、录屏投屏、屏幕适配，共 73 个工具。

什么时候仍然用 uiautomator2：上百步固定回归、需要断言与 CI 报告、或需要 OCR / 图像处理。 注意：两者争抢同一个设备端无障碍连接，同一台设备上不能同时运行。

Linux Boards

不止 Android：也能接 Linux 工控主板

带 adb 服务的 Debian / Ubuntu / Buildroot / Yocto 主板（RK3568、RK3576 等）接上就能用。平台自动识别， Android 专有功能自动隐藏 —— 不会出现「点了就报错」或「白等 10 秒才失败」。

基础能力开箱可用

终端（adb shell,v2: PTY）、文件 push / pull、进程（带完整命令行）、CPU / 内存 / 温度、 端口转发、串口，全部照常。

日志换成 journalctl / dmesg

有 systemd 走 journalctl -o json，无 systemd 自动回落 dmesg；级别、搜索、暂停 与 aya_logcat、aya_logcat_wait 表现一致。

Android 专有功能自动隐藏

应用管理、布局树、截图录屏、输入注入、投屏、WebView 调试在 Linux 上不存在：面板直接隐藏，对应 MCP 工具 在几十毫秒内返回 NOT_SUPPORTED 并说明原因。

平台自动判定

getprop + /etc/os-release + app_process 综合判断，按设备缓存 5 分钟； 同时插着 Android 与 Linux 板子时，各自按各自的平台走。

Enable MCP

打开 MCP 服务：入口就在设置里

服务由 AYA 桌面端托管，没有命令行、没有额外进程。关掉这个开关，AYA 就回到原版状态。

  1. 打开「设置」 主界面右上角的齿轮图标，或菜单 工具 → 设置。
  2. 切到 MCP 分组 弹窗左侧「外观 / ADB / MCP」，点最下面的 MCP。
  3. 勾选「启用 MCP 服务」 立即在本机启动，默认端口 7788，并自动生成访问令牌。
  4. 按需放开能力 要点击、输入、shell 就勾「允许写操作」；要跨机连接再勾「允许局域网访问」。

Quick Start

三步，把手机交给 AI

无需 Root，手机上也无需安装任何 App。只要开启 USB 调试 / 无线调试，电脑上跑着 AYA 就行。

开启 MCP 服务

设置 → MCP → 勾选「启用 MCP 服务」，默认端口 7788。需要点击、安装、shell 时再勾「允许写入操作」 （面板截图）。

复制配置片段

弹窗给出三种写好的配置：stdio（推荐）、stdio（无 env）、HTTP。点「复制」，端口与令牌已填好。

粘贴到 AI 客户端

CodeBuddy 粘贴到 ~/.codebuddy/mcp.json；其他 MCP 客户端同理，重连后即可看到 aya_* 工具列表。 

// AYA 设置 → MCP → 查看配置，直接复制即可（令牌已填好）
{
  "mcpServers": {
    "aya": {
      "type": "stdio",
      "command": "C:/Path/To/AYA.exe",      // 客户端用 AYA 自带的 node 启动桥接脚本
      "args": [
        "resources/mcp/aya-mcp-stdio.cjs",
        "--url=http://127.0.0.1:7788/mcp",
        "--token=<your-token>"
      ],
      "env": {
        "ELECTRON_RUN_AS_NODE": "1",
        "AYA_MCP_URL": "http://127.0.0.1:7788/mcp",
        "AYA_MCP_TOKEN": "<your-token>"
      },
      "description": "AYA Android device control"
    }
  }
}
// 客户端找不到 AYA.exe 时，用系统 node 直接跑桥接脚本
{
  "mcpServers": {
    "aya": {
      "type": "stdio",
      "command": "node",
      "args": [
        "resources/mcp/aya-mcp-stdio.cjs",
        "--url=http://127.0.0.1:7788/mcp",
        "--token=<your-token>"
      ],
      "description": "AYA Android device control (no env fallback)"
    }
  }
}
// HTTP 无状态：切换写权限后需重新 tools/list（或重连）
{
  "mcpServers": {
    "aya": {
      "type": "http",
      "url": "http://127.0.0.1:7788/mcp",
      "headers": { "Authorization": "Bearer <your-token>" },
      "description": "AYA Android device control"
    }
  }
}
桥接脚本收到 tools/list_changed 会通知客户端热刷新；客户端不支持热更新时重连一次即可。

Security

默认收紧，能力给你、风险留给自己可控

MCP 服务跑在你自己的电脑上，设备数据不出本机；危险能力需要你显式授权。

  • 只监听 本机或内网：外部网络无法访问，端口 1024–65535，默认 7788。
  • Bearer Token 鉴权：首次开启时生成并持久化，可随时「重置访问令牌」。
  • 写操作默认隐藏：44 个写工具需勾选才暴露，29 个只读工具始终可用。
  • Origin 校验 + 2MB 请求体限制：防跨站调用与超大 payload。
  • shell 有兜底：aya_shell 30s 超时、输出截断 20000 字符。

FAQ

常见问题

AYA MCP 和原版 AYA 是什么关系？

基于开源项目 AYA（AGPL-3.0）二次开发， 完整保留原版投屏、文件管理、日志、性能、Shell 等桌面能力，只新增了 MCP 服务层；关掉 MCP 开关就是原版 AYA。

需要 Root 或在手机上安装 App 吗？

都不需要。AYA 走 adb，只需在手机上开启 USB（或无线）调试并授权本机。

客户端只看到 29 个只读工具怎么办？

说明未勾选「允许写入操作」。勾选后重连或等 tools/list_changed 热刷新，即可看到全部 73 个； 目标工具是只读还是写可在 工具清单 里查。

aya_tap 返回 STALE_SNAPSHOT？

快照 60s 过期，输入类操作后立即失效。重新 aya_ui_dump 拿新的 snapshotId 与 nodeIndex 再点。

点开播放器控制栏后读不到控件？

这类控件只停留 1–3 秒。用 aya_tap 默认的 withUi（点完立刻抓一帧），或把「点击 → 等待 → 再点击」合成一次 aya_batch。

MCP 开关打不开，提示端口被占用？

默认 7788 被占。在设置里换一个 1024–65535 的端口重试，设置项会直接显示错误原因。

支持哪些 AI 客户端？

任何支持 MCP 的客户端都可以：CodeBuddy、WorkBuddy、Claude Desktop、Cursor、Cline 等。配置片段在 AYA 设置里一键复制。

MCP 支持局域网或远程访问吗？

默认不支持：服务只监听 127.0.0.1，局域网与公网都连不上。确有跨机需求时，用 SSH 隧道 / frp / ngrok 转发本机端口，开放前务必开启 Bearer Token，且只暴露给可信网络。

支持 Linux 工控主板吗？

支持带 adb 服务的 Debian / Ubuntu / Buildroot / Yocto 主板（RK3568、RK3576 等）。终端、文件、进程、性能、 日志（journalctl / dmesg）、端口转发、串口可用；应用管理、布局树、截图录屏、输入注入、投屏、WebView 调试 依赖 Android 专有命令，在 Linux 上自动隐藏，对应 MCP 工具返回 NOT_SUPPORTED 并说明原因。

AYA MCP 和 Python uiautomator2 有什么区别？该用哪个？

同一台 RK3576 / Android 14 上交替实测：层级 131 ms vs 309 ms、点击 91 vs 180 ms、滑动 390 vs 1160 ms、写文本 93 vs 253–476 ms、截图 14 KB vs 6.2 MB。模型即席操作选 aya；上百步固定回归、要断言与 CI、或要 OCR / 图像处理选 u2。两者争抢同一个设备端无障碍连接，不能同时运行。
