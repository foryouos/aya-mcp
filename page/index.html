Model Context Protocol

MCP 是什么？为什么手机需要它

MCP 是 AI 客户端与工具之间的开放协议。过去 AI 只能"教你怎么操作手机"，现在它能自己调工具、看结果、再决定下一步。 AYA MCP 就是把 adb 的几十年积累，翻译成 AI 听得懂、调得动的 73 个标准工具。

会说人话就够了

不用记 adb shell am start -n ...。自然语言描述目标，AI 自己选择并组合工具，失败还会根据返回的错误自我纠正。

看得见界面，不只是命令

aya_ui_dump 返回带坐标与索引的 UI 层级树，aya_screencap 回传截图。AI 既读结构也看画面，点得准、判得对。

一次调用干完一串动作

aya_batch 串行执行最多 20 个动作，中间不经过模型思考，彻底避开播放器控制栏、Toast 这类 1–3 秒就消失的控件。

关于二次开发：本分支基于开源项目 AYA（ liriliri/aya，作者 surunzi，AGPL-3.0） 二次开发，完整保留原版投屏、文件管理、日志、性能、Shell 等桌面能力，仅新增 MCP 服务层：设置 → MCP → 启用即可，不影响原有使用习惯。

Enable MCP

打开 MCP 服务：入口就在设置里

MCP 服务由 AYA 桌面端托管，没有命令行、没有额外进程。按下面四步点开并勾选「启用 MCP 服务」就算打开了；关掉这个开关，AYA 就回到原版状态。

  1. 打开「设置」 点主界面右上角的齿轮图标，或走菜单 工具 → 设置。
  2. 切到 MCP 分组 弹窗左侧只有「外观 / ADB / MCP」三项，点最下面的 MCP。
  3. 勾选「启用 MCP 服务」 勾上后服务立即在本机启动，默认端口 7788，并自动生成访问令牌。
  4. 按需放开能力 需要点击、输入、shell 就勾「允许写操作」；要跨设备连接再勾「允许局域网访问」。
面板上每一项管什么 跟着截图看
控件默认作用
启用 MCP 服务打开总开关。开启即监听本机端口并提供 aya_* 工具；首次开启会自动弹出配置片段弹窗。
允许写操作按需暴露点击、滑动、输入、按键、shell、安装卸载等写工具。不勾时客户端只能读屏、抓日志、传文件。
允许局域网访问关闭勾选后监听地址从 127.0.0.1 变为 0.0.0.0，同网段的其它机器可按状态行给出的 IP 连接。
端口7788取值范围 1024–65535。被占用时改一个数字，地址会随之更新。
状态行—绿点即「运行中」，后面依次是完整端点地址与当前暴露的工具数量，改开关后会实时刷新。
查看 MCP 配置—弹出 stdio（推荐）/ stdio（无 env）/ HTTP 三种片段，令牌已填好，点「复制」即可粘到客户端。
重置访问令牌—令牌泄露或换机器时点它，旧令牌立即失效，记得同步更新客户端配置。
路径速记：工具栏齿轮（或菜单 工具 → 设置）→ 左侧 MCP → 勾选 启用 MCP 服务 → 点 查看 MCP 配置 复制片段。状态行显示的工具数会随「允许写操作」变化，客户端没刷新时重连一次即可。

Quick Start

三步，把手机交给 AI

无需 Root，手机上也无需安装任何 App。只要开启 USB 调试 / 无线调试，电脑上跑着 AYA 就行。

开启 MCP 服务

设置 → MCP → 勾选「启用 MCP 服务」。服务随应用启动自动拉起，默认端口 7788，同时生成访问令牌。需要点击、安装、shell 等能力时，再勾选「允许写入操作」。 具体入口与面板截图见上一节。

复制配置片段

弹窗里直接给出三种写好的配置：stdio（推荐）、stdio（无 env）、HTTP。点「复制」，片段里已带好端口与令牌。

粘贴到 AI 客户端

CodeBuddy：设置 → MCP → 添加 MCP，粘贴到 ~/.codebuddy/mcp.json。其他支持 MCP 的客户端同理，重连后即可看到 aya_* 工具列表。 

// AYA 设置 → MCP → 查看配置，直接复制即可（令牌已填好）
{
  "mcpServers": {
    "aya": {
      "type": "stdio",
      "command": "C:/Path/To/AYA.exe",      // 客户端用 AYA 自带的 node 启动桥接脚本
      "args": [
        "resources/mcp/aya-mcp-stdio.cjs",
        "--url=http://127.0.0.1:7788/mcp",
        "--token=<your-token>"
      ],
      "env": {
        "ELECTRON_RUN_AS_NODE": "1",
        "AYA_MCP_URL": "http://127.0.0.1:7788/mcp",
        "AYA_MCP_TOKEN": "<your-token>"
      },
      "description": "AYA Android device control"
    }
  }
}
// 客户端找不到 AYA.exe 时，用系统 node 直接跑桥接脚本
{
  "mcpServers": {
    "aya": {
      "type": "stdio",
      "command": "node",
      "args": [
        "resources/mcp/aya-mcp-stdio.cjs",
        "--url=http://127.0.0.1:7788/mcp",
        "--token=<your-token>"
      ],
      "description": "AYA Android device control (no env fallback)"
    }
  }
}
// HTTP 无状态：切换写权限后需重新 tools/list（或重连）
{
  "mcpServers": {
    "aya": {
      "type": "http",
      "url": "http://127.0.0.1:7788/mcp",
      "headers": { "Authorization": "Bearer <your-token>" },
      "description": "AYA Android device control"
    }
  }
}
桥接脚本通过 SSE 收到 notifications/tools/list_changed 后会通知客户端热刷新；客户端不支持热更新时重连一次即可。 端口被占用可在设置里改（1024–65535），令牌泄露可点「重置访问令牌」。

Security

默认收紧，能力给你、风险留给自己可控

MCP 服务跑在你自己的电脑上，设备数据不出本机；危险能力需要你显式授权。

  • 只监听 本机或内网：外部网络无法访问，端口范围 1024–65535，默认 7788。
  • Bearer Token 鉴权：令牌首次开启时生成并持久化，可随时「重置访问令牌」。
  • 写操作默认隐藏：44 个写工具需勾选「允许写入操作」才暴露，29 个只读工具始终可用。
  • Origin 校验 + 2MB 请求体限制：防止网页跨站调用与超大 payload 打爆服务。
  • shell 有兜底：aya_shell 30s 超时、输出截断 20000 字符，破坏性命令仍由客户端按 readOnlyHint 弹确认框。
关于局域网 / 远程访问：MCP 服务默认只监听本机回环地址 127.0.0.1，局域网内其它设备、以及公网都无法直接连上，这是有意的安全设计——设备数据始终留在你的电脑上。 如果你确实需要「手机接在 A 机器、AI 客户端跑在 B 机器」这类跨机/远程场景，可以自行用 SSH 隧道、frp、ngrok 等工具把本机的 127.0.0.1:7788 映射出去；但在开放端口前，请务必确认已开启 Bearer Token，并只允许可信网络访问，不要直接把端口暴露到公网。

FAQ

常见问题

AYA MCP 和原版 AYA 是什么关系？

本分支基于开源项目 AYA（liriliri/aya，作者 surunzi，AGPL-3.0） 二次开发，完整保留原版投屏、文件管理、日志、性能、Shell、应用管理等桌面能力，只新增了 MCP 服务层。 关闭 MCP 开关时，它就是原版 AYA。

需要 Root 或在手机上安装 App 吗？

都不需要。AYA 通过 adb 与设备通信，只需在手机上开启 USB 调试（或无线调试）并授权本机调试。

客户端只看到 29 个只读工具怎么办？

说明未勾选「允许写入操作」。勾选后重连 MCP 服务，或等待 tools/list_changed 热刷新，即可看到全部 73 个工具； 也可以先在 完整工具清单 里确认目标工具是只读还是写。

aya_tap 返回 STALE_SNAPSHOT？

UI 快照 60s 过期，且任何输入类工具执行后会立即失效。重新 aya_ui_dump 拿到新的 snapshotId 和 nodeIndex 再点。

点开播放器控制栏后读不到控件？

这类控件只停留 1–3 秒。用 aya_tap 默认的 withUi（点完立刻抓一帧）、或把「点击 → 等待 → 再点击」合成一次 aya_batch，就能避开模型思考延迟。

MCP 开关打不开，提示端口被占用？

默认 7788 被其他进程占了。在设置里换一个 1024–65535 的端口重试，设置项会直接显示错误原因。

支持哪些 AI 客户端？

任何支持 MCP 的客户端都可以，包括 CodeBuddy、WorkBuddy、Claude Desktop、Cursor、Cline 等。配置片段在 AYA 设置里一键复制。

MCP 支持局域网或远程访问吗？

默认不支持。服务只监听 127.0.0.1（本机回环），局域网内其它设备和公网都连不上，设备数据不出本机。这是默认的安全设定。 若有跨机需求（例如手机接在一台机器、AI 客户端在另一台），可用 SSH 隧道、frp、ngrok 等把本机 127.0.0.1:7788 端口转发出去；开放前请务必开启 Bearer Token，并只暴露给可信网络，切勿直接面向公网。
